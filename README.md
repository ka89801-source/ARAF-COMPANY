# أعراف للأعمال — بوابة المنشآت

بوابة اشتراكات قانونية مخصصة للشركات والمؤسسات والجمعيات، بتصميم «الفخامة الهادئة» وربط مباشر وآمن مع Supabase.

## الملفات

| الملف | الوظيفة |
|---|---|
| `index.html` | الصفحة التسويقية والباقات وطلب الانضمام |
| `login.html` | دخول المنشآت برمز المنشأة والرقم السري |
| `platform.html` | بوابة المنشأة والرصيد والخدمات والطلبات |
| `accounts.js` | بيانات العرض العامة للباقات ورقم التواصل مع المحامي فقط |
| `supabase-config.js` | إعداد عميل Supabase بالمفتاح العام المسموح للواجهة |
| `api/` | حفظ طلبات الخدمات والتفعيل وإرسال تنبيهات البريد |
| `server/business-api.js` | وظائف الخادم المشتركة دون كشف المفاتيح للواجهة |
| `terms.html` | الشروط والأحكام |
| `logo.png` | الشعار المعتمد |

## طريقة العمل

- المصادقة تتم بواسطة Supabase Auth.
- واجهة الدخول تحول رمزًا مثل `ARF-1001` داخليًا إلى البريد النظامي `arf-1001@business.araf.online`.
- بيانات المنشأة موجودة في `business_entities` ومرتبطة بحساب Auth عبر `auth_user_id`.
- الطلبات تمر عبر API الخادم، ثم تُنشأ بواسطة الدالة الآمنة `business_create_request` ويُرسل تنبيه بالبريد.
- «طلبات منشأتي» تقرأ الطلبات الفعلية من `business_requests`.
- استهلاك الباقة يُقرأ من `business_usage`.
- سياسات RLS تمنع كل منشأة من رؤية بيانات منشأة أخرى.

## تفعيل منشأة جديدة

1. أنشئ مستخدمًا من **Supabase → Authentication → Users**.
2. استخدم بريدًا نظاميًا مشتقًا من رمز المنشأة، مع تفعيل **Auto confirm user**.
3. أضف المنشأة إلى `business_entities` واربطها بقيمة `User UID`.
4. حدد الباقة ودورة الاشتراك. أضف المحامي المخصص لباقة «نمو»، وفريق المحامين لباقة «بلس»؛ باقة «أساس» بلا محامٍ مخصص.
5. سلّم العميل رمز المنشأة والرقم السري فقط.

## مفاتيح الباقات

| المفتاح | الباقة | السعر الشهري |
|---|---|---:|
| `asas` | أعراف أساس | 500 ر.س |
| `numu` | أعراف نمو | 2,500 ر.س |
| `plus` | أعراف بلس | 5,000 ر.س |

## الأمان

- لا توجد حسابات أو أرقام PIN داخل ملفات GitHub.
- لا تستخدم مفتاح `service_role` في أي ملف عام.
- مفتاح Supabase الموجود في `supabase-config.js` هو المفتاح العام للواجهة، والحماية الفعلية تعتمد على Auth وسياسات RLS.
- الملاحظات الداخلية محفوظة في جدول مستقل لا يستطيع حساب المنشأة قراءته.


## تجهيز الإنتاج على Vercel

1. شغّل `supabase/business-refinements-20260831.sql` مرة واحدة في Supabase SQL Editor.
2. اربط هذا المستودع بمشروع Vercel.
3. أضف متغيرات البيئة التالية في Vercel:
   - `SUPABASE_URL`
   - `SUPABASE_SECRET_KEY` (المفتاح الجديد الذي يبدأ بـ `sb_secret_`)
   - `RESEND_API_KEY`
   - `BUSINESS_ALERT_EMAIL=ka89801@gmail.com`
   - `BUSINESS_ALERT_FROM` لعنوان إرسال موثّق في Resend
4. انشر المشروع ثم اختبر طلب تفعيل وطلب خدمة واحدًا.

مفتاح Supabase السري ومفتاح Resend يبقيان في Vercel فقط. لا يُرسَل أي نموذج أو طلب تفعيل عبر واتساب؛ واتساب مخصص للتواصل المباشر مع المحامي أو فريق المحامين حسب الباقة.
